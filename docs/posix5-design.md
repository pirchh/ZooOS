# POSIX layer, step 5a: a C toolchain and freestanding C programs

Status: implemented and verified 2026-10-30 (results in docs/verification.md).
Step 5 of strategy A (docs/feasibility/wine-hosting.md) is a C toolchain
and a libc. It is split: **5a** (this step) builds and runs C programs
without a libc; **5b** (proposed) ports a libc onto the ZooOS calls.

## 1. Toolchain

- Zig 0.16.0, used as `zig cc` (clang 21.1.0 and lld), downloaded into
  `tools/zig/` with the owner's approval; version, source, size and SHA-256
  in tools/zig/README.md. Nothing is installed system-wide.
- Chosen because one archive provides the compiler, the linker and libc
  sources (musl) for step 5b.
- xtask refuses any other `zig version`. Without the toolchain, C programs
  are left out and the `c-program` case reports `SKIP` (never `OK`).

## 2. How C programs are built

- Target `x86_64-freestanding-none`, `-O2`, `-std=c11`, warnings as errors,
  no stack protector, static and non-PIE, linked at `0x200000` with entry
  `_start` (the same layout as the Rust user programs).
- `c/crt/start.c`: `_start(first, second)` calls `main(first, second)`
  and exits with its result (the kernel starts threads with the start-up
  handles in `rdi`/`rsi` and a C-entry-aligned stack).
- `c/crt/string.c`: `memcpy`, `memmove`, `memset`, `memcmp`, `strlen`,
  which the compiler may call in freestanding code.
- `c/include/zoo.h`: inline system-call wrappers. The numbers come from
  `zoo_abi.h`, **generated by xtask from the `zoo-abi` crate** at every
  build, so C and Rust cannot disagree.
- Every built program is checked with the kernel's own ELF parser and load
  range before it is packed into the initrd as `bin/<name>`.

## 3. Verification

`c-program` case: boot the normal image, type `run puffin-test` in
the shell, require `PROC exit pid=20 name=puffin-test code=0`.
PuffinTest (`c/programs/puffin-test.c`) checks:

- the ABI version;
- CRC-32 of "The quick brown fox jumps over the lazy dog" equals the
  standard check value `0x414FA339`;
- a floating-point square root of 2 to 1e-12;
- 64 KiB from `mem_alloc` is zeroed and holds what it writes.

It logs its results with a hand-written formatter.

## 4. Step 5b (proposed)

Port a libc (musl's sources ship with the toolchain) by replacing its
Linux system-call layer with ZooOS calls: memory (`mmap` on `vm_*`),
threads (`clone`/futex on `thread_create`/`futex_*`, TLS on
`set_fs_base`), files (on the directory-handle calls; this needs file
descriptors, which ZooOS does not have yet), and `exit`. File descriptors,
`stat`, time and environment/arguments for processes are the main new
kernel work it implies.
